# Repo Kickoff

## Trigger

Use before editing an unfamiliar repository or unfamiliar subsystem.

## Procedure

1. Identify build system, app shape, and important top-level directories.
2. Trace the target feature or subsystem before proposing edits.
3. Confirm likely change points and validation paths.
4. Note risky areas and unresolved dependencies.

## Exit Criteria

- likely change surface is identified
- validation path is understood
- risky unknowns are visible before implementation
